# Actual-interface celestial guiding — 0.3.12 candidate

- Evidence: 0.3.11 capture `155159-172` contains 185 ordinary→water-reflection→sun records with no roulette amplification; all first receivers are pool-wall points. Another 64 records cross water, scatter, then exit. Counts are thresholded/capped records, with repeated view runs, not whole-image event frequencies.
- Existing submerged horizontal guiding cannot propose the dry reflection class. Even the measured 0.426° mesh tilt can move an underwater solar connection outside its narrow proposal.
- At an eligible offline ordinary vertex, trace one deterministic pilot in the horizontal reflected/refracted solar-center direction. Save/restore the complete payload. The pilot consumes no RNG, changes no contribution/history state, and selects a proposal normal only.
- For a matching water interface, use the actual geometric normal for refraction and the actual wave-adjusted reflection normal for reflection. Establish this fixed context before direct-light and continuation samples. If the pilot fails, submerged vertices retain the old horizontal proposal; dry vertices retain BSDF sampling.
- Sample the unchanged 5%-expanded solar proposal, mapped through the selected normal. Reflection preserves solid angle; refraction uses eta²*cosWater/cosAir. Keep the known forward density for generated samples, and support-tested evaluation for arbitrary directions.
- Mix 50% with the complete original BSDF. Use the same context in celestial/static NEE competitors and continuation throughput/MIS. Retain conditional lobe ray cones and existing supported-leg roulette protection.
- Actual tracing still decides Fresnel, absorption, obstruction and final solar visibility. No extra radiance estimator, clipping, changed water geometry or wave model. This is direction guiding, not a manifold connection solver.
- Limits: a pilot can select the wrong triangle or miss a narrow interface; spatially varying normals, multiple specular interfaces and shading-normal origin offsets remain open. One additional trace per eligible scattering vertex has a GPU cost requiring game measurement. Realtime runs no pilot.
- Verify extracted FP32 mapping/PDFs, boundary samples, independent planar transport means/variance, payload restoration and disabled-mode behavior; run existing material/medium/MIS/probe tests, build all variants, verify packaged shaders and deploy reversibly. User GPU acceptance remains required before declaring convergence solved.
