# 离线渲染静态光源采样设计

## 目标

为 Caustica 的离线渲染加入静态光源显式采样。渲染器不再完全依靠随机反射光线偶然碰到火把、灯笼、萤石或岩浆，而是在每个适合接收直接光的表面主动抽取一个光源并检测可见性。

第一阶段需要在相同 SPP 下明显降低黑暗室内场景的磨砂噪声和零星亮点，同时保持离线累计的高反射次数与丰富间接光照。

## 用户确认的范围

第一阶段支持：

- 带有原版亮度值的静态可见方块，例如火把、灯笼、萤石、海晶灯和红石灯；
- 岩浆等拥有实际发光表面的静态流体；
- Minecraft 的隐形“光源方块”，包括其 0～15 级亮度；
- 方块放置、移除、状态变化和光源方块亮度变化后的实时更新。

第一阶段暂不支持：

- 生物、掉落物、粒子和其他动态实体发光；
- 手持光源；
- 原版亮度值为 0、仅由 LabPBR 材质贴图额外定义的发光区域；
- ReSTIR、空间降噪、时间降噪和辐照度缓存；
- 实时渲染路径中的静态光源显式采样。

普通发光方块如果同时具有 LabPBR `_s` 材质，仍可使用该材质的逐像素发光强度；第一阶段只是不主动发现“原版完全不发光、仅材质包让它发光”的方块。

不得复制同级付费光影包的代码。不得执行 Git 暂存、提交或推送。

## 总体方案

采用混合光源表示：

1. 可见的普通发光方块和岩浆使用其实际可见三角形作为面光源。
2. 隐形光源方块使用位于方块中心的点光源。
3. 离线路径追踪器在每个普通材质交点抽取一个静态光源，发射一条可见性射线并计算直接光照。
4. 面光源使用多重重要性采样（MIS）与原有材质反射采样组合，避免重复计算造成亮度增加。
5. 光源方块是不可被普通路径直接撞到的点光源，因此其直接光贡献不需要与“撞到光源”的路径组合。

静态光源采样只在离线渲染真正开始累计时启用。实时模式和离线模式等待相机静止、等待冻结游戏刻的阶段保持原有效果和开销。

## 可见发光方块

### 收集

现有地形网格生成器已经逐方块读取 `BlockState.getLightEmission()`，并把 0～15 映射到 0～1。网格生成时为每个实际生成且亮度大于 0 的三角形附带一个静态光源候选记录。

候选记录包含：

- 三角形三个顶点；
- 三个顶点对应的方块图集 UV；
- 表面法线和面积；
- 方块颜色乘数；
- 原版发光强度；
- 对应材质是否具有 LabPBR `_s`；
- 所属区块和三角形编号。

只有经过正常面剔除后实际存在于光追几何体中的表面才成为光源。被完整方块遮住的内部表面不会进入列表。

### 颜色与强度

抽样到三角形上的一点后，ray-generation 着色器使用插值 UV 读取方块图集：

- 普通材质使用线性化后的颜色乘以方块颜色乘数；
- alpha cutout 使用与现有 any-hit 路径一致的透明度规则，透明 texel 不贡献光；
- 如果候选具有 `_s`，使用与 closest-hit 相同的 `_s` alpha 解码替换原版发光强度；
- 否则使用 `原版亮度 / 15`；
- 最终表面辐射亮度继续使用现有 `EMISSIVE_STRENGTH = 3.0` 标度，保证直接撞到光源与主动采样使用同一个亮度模型。

这使显式采样不会把普通材质和 LabPBR 材质渲染成两个不同亮度体系。

## 隐形光源方块

地形扫描在跳过无可见模型的方块之前识别 `Blocks.LIGHT`：

- 亮度 0 不建立光源；
- 亮度 1～15 在方块中心建立白色、向四周发光的点光源；
- 光源方块保持完全不可见，不参与反射、遮挡和相机直接显示；
- 点光源使用平方反比衰减和现有阴影可见性射线；
- 彩色玻璃与水仍可通过现有可见性路径衰减或染色它的光。

点光源强度按一个半径为 0.25 方块、表面辐射亮度为
`EMISSIVE_STRENGTH * level / 15` 的虚拟白色球体换算：

```text
intensity = EMISSIVE_STRENGTH * (level / 15) * PI * 0.25²
```

这个球体只用于确定能量，不会显示出来。距离平方最低限制为 `0.25²`，避免观察点非常靠近方块中心时产生无限亮度。

第一阶段使用点光源，因此光源方块产生清晰阴影；后续如有需要可以单独增加可调软阴影半径。

## 光源列表与更新

每个已发布地形区块保存自己的 CPU 静态光源候选列表。全局静态光源管理器在以下情况重建紧凑 GPU 列表：

- 新区块发布；
- 区块移除；
- 脏区块重建；
- 地形坐标重定位；
- 资源包重载导致材质标志变化；
- 首次进入离线模式且 GPU 列表尚未建立。

GPU 列表中的面光源顶点使用与当前 TLAS 相同的重定位坐标。重定位时必须重建列表，不能继续使用旧坐标。

每个光源具有非零抽样权重：

- 面光源：`面积 * 原版发光强度`；
- 光源方块：点光源强度。

管理器生成归一化累计权重表。着色器用一个随机数二分查找光源，得到该光源的选择概率。LabPBR 可能使某个被抽到的 texel 实际不发光，这个样本返回 0；这不会改变正确性，只会略微降低抽样效率。

GPU 光源数据通过 buffer device address 加入现有 `WorldPush`，避免新增一整套描述符集合。推送数据包含光源缓冲地址、光源数量和总权重。

当没有静态光源时，着色器跳过该步骤，行为与当前版本一致。

## 三角形与 MIS 对应关系

为了在随机反射光线撞到发光三角形时计算正确的 MIS 权重，每个地形三角形增加一个独立的 32 位光源编号 sidecar 缓冲：

- 非光源三角形为 `0xFFFFFFFF`；
- 光源三角形保存其在当前全局 GPU 光源列表中的编号；
- sidecar 只增加每个三角形 4 字节，不扩大现有每三角形 48 字节材质记录；
- `Section` 表项增加 sidecar 缓冲地址；
- closest-hit 将光源编号写入 ray payload。

光源列表重建时同步修补相关区块的 sidecar 编号。列表和 sidecar 必须作为同一版本发布，不能让着色器看到新列表与旧编号的组合。

## 路径追踪计算

### 主动抽取面光源

在普通不透明或 cutout 表面：

1. 按累计权重选择一个光源。
2. 面光源均匀抽取三角形面积上的一点。
3. 计算接收面与发光面的夹角、距离、材质 BRDF 和光源概率密度。
4. 向抽样点发射现有可见性射线，最大距离略短于光源距离，避免目标三角形遮挡自己。
5. 计算直接光贡献。
6. 使用 power heuristic 组合光源概率密度与当前 diffuse/GGX 混合材质的概率密度。

面光源从背面观察时不贡献直接光，防止一个单面火把或岩浆表面从错误方向发光。

### 随机路径撞到面光源

路径状态记录上一跳的材质采样概率密度以及是否为 delta 路径：

- 相机直接看到光源时保留完整发光贡献；
- 镜面、玻璃和水等 delta 路径撞到光源时保留完整发光贡献；
- 普通 diffuse/GGX 路径撞到已登记面光源时，以相同 power heuristic 计算另一侧 MIS 权重；
- 未登记光源继续按当前方式累加，不参与第一阶段显式采样。

这样不会因为加入主动抽样而使火把、萤石或岩浆整体变亮一倍。

### 点光源

点光源方向由接收点到方块中心唯一确定，使用点光源强度除以距离平方。它不能被普通随机方向以非零概率撞到，因此直接光权重为 1，不参与面光源 MIS。

### 适用反射

第一阶段在每个普通材质反射点抽取一个光源，包括 diffuse 与 GGX 接收面。玻璃和水自身仍通过反射或折射继续路径，不在界面处额外抽取静态光源。后续路径到达普通表面后仍可获取静态直接光。

光源采样不修改最大反射次数和俄罗斯轮盘策略。

## 离线模式接入

新增的光源采样由 `WorldPush.flags` 中一个独立标志控制。只有以下条件同时满足时开启：

- Offline Rendering 已启用；
- 游戏刻已冻结并通过现有状态机允许累计；
- 当前静态光源列表已经与地形场景版本同步。

如果列表仍在重建，本帧显示当前原始结果但不把它计入离线历史，避免把使用旧光源数据的帧混入累计。

光源列表变化沿用现有 terrain scene revision，使离线累计样本立即清零。SPP 权重累计公式不变。

## 资源生命周期和错误处理

- 静态光源 GPU 缓冲、累计权重和三角形 sidecar 都由地形渲染资源拥有；
- 区块替换使用现有延迟销毁机制，不能销毁仍被飞行中帧读取的缓冲；
- 世界退出、RT 关闭和渲染器销毁时释放全部光源资源；
- 光源数量为 0 时仍提供安全的空状态，不允许地址 0 被着色器解引用；
- 光源数量或缓冲大小溢出时记录一次有界警告，并使该帧不进入离线累计，不能使用截断后概率错误的列表；
- 光源列表与 sidecar 发布失败时继续使用上一个完整版本，不能部分更新。

## 测试策略

### 自动测试

新增不依赖 Minecraft 和 Vulkan 的行为测试，覆盖：

- 光源方块亮度 0 不生成记录；
- 亮度 1、8、15 的点光强度单调增加且符合换算公式；
- 面光源面积和亮度权重计算；
- 空列表、单光源和多光源累计权重；
- 随机值位于 0、分界点附近和 1 以下时选择正确光源；
- 非光源三角形使用 `0xFFFFFFFF`；
- power heuristic 在零概率、相等概率和极端概率下保持有限值；
- 离线未开始累计时光源采样标志关闭；
- 列表版本落后于 terrain scene revision 时禁止累计。

现有离线渲染、帧生成开关和构建环境测试必须继续通过。

### 编译验证

- Java 编译通过；
- Slang 的 EXT SER 与 NV SER 两个 ray-generation 版本均通过编译；
- `spirv-val --target-env vulkan1.2` 通过；
- 完整本地构建成功生成 `build/libs/caustica-0.1.0.jar`。

### 游戏内验证

在相同分辨率、SPP、反射次数和曝光设置下比较：

1. 完全封闭的午夜房间，只有一根火把；
2. 同一房间分别使用萤石和灯笼；
3. 岩浆池照亮附近墙面；
4. 隐形光源方块分别设置亮度 1、8、15；
5. 在光源与墙面之间放置实体方块、彩色玻璃和水；
6. 放置、移除光源以及修改光源方块亮度，确认样本数清零并重新累计；
7. 相机直接观察火把、萤石和岩浆，确认加入显式采样后没有明显整体增亮。

成功标准：

- 光源方块能够照亮 Caustica 场景且自身不可见；
- 亮度等级能够明显控制照明强弱；
- 火把房间在相同 SPP 下比当前版本更快消除磨砂噪声和亮点；
- 普通发光方块与岩浆没有因重复计算出现明显亮度翻倍；
- 阴影遮挡、彩色玻璃染色和水体衰减继续生效；
- 离线累计、HUD、自动冻结、DLSS 禁用与帧生成禁用行为无回归。
