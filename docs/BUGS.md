# Bug 记录

## WG-062：云影移动时呈"一顿一顿"的跳动

- 现象：云层移动时，从地面的云影看是不连续的"一抽一抽"，而不是平滑滑动。与雷暴雾气、天气亮度层次同轮反馈，后两项已修复。
- 已排查（均未定位）：`cloudTime` 在 Java 侧由 `(level.getGameTime() + partial) / 20.0 % 3600.0` 得到，含子 tick 插值，理应连续；`cloudAnchor.w` 只是 `CLOUD_SPEED` 设置；云影的密度场只用世界坐标与 `cloudCoordinates`，且以 `viewDetail = false` 调用，不含任何相机相关项，因此本身是纯世界空间场、应当平滑。
- 本轮（凑巧可能相关）：云影求交平面由云层基底改为层中点。若跳动源自"天气驱动的云层高度"（`EnvironmentAttributes.CLOUD_HEIGHT` → `weatherColor.w`）变化时采样位置滑动，此改动会减轻它。
- 其他怀疑：`cloudTime % 3600.0` 的 wrap（每 3600 秒游戏时间跳一次，与"频繁跳动"的现象不符）；`cloudAnchor.xy` 随地形 rebase 跳变（代码注释称已保证跨 rebase 连续）。
- 待用户确认：跳动频率（每秒几次、是否与 20 Hz 游戏 tick 同步）、是否只在特定天气、是否随视角或所在位置变化。
- 用户复测：抽动暂未复现，用户要求先搁置。上一轮已顺带把云影改为按层中点平面求交，若成因是天气驱动的云层高度变化，该改动即已消除它。状态改为待复现，优先级低于其它云相关项。

## WG-061：远景微缩模式的景深边缘闪烁未解决

- 现象：开启"远景微缩"（固定焦距）模式后，树叶等高频几何的边缘仍有明显闪烁与噪点；同场景切到准星自动对焦模式后明显改善。用户判定"还是不行"，先登记为未解决项。
- 已确认的事实：两种模式共用同一套采样、权重与时间累积代码，差异只在弥散圆响应公式；远景微缩的半径上限按显示短边缩放（`12 px @ 1080p`、近处 2 倍，2560×1440 下即 32 px），盘更大而采样数量相同，因此盘内采样密度明显低于自动对焦模式。
- 怀疑方向（未验证）：焦平面附近的像素真实弥散圆只有亚像素，但扩散搜索会把盘半径拉到远处失焦物的值，于是半径在 `0.56 px` 与上限之间跳变；这些像素本应清晰，噪声因此最刺眼。与用户观察到的"越接近聚焦位置闪烁越严重"一致。
- 待办（按代价从低到高）：让扩散半径随距离连续增长；把扩散判定从硬 max 改为按覆盖程度加权；引入基于模糊结果自身的邻域颜色钳制（需要独立 pass，当前只能借用清晰输入的范围，对模糊区偏松）。
- 状态：未解决，尚无修复。时间累积已在 WG-052 下改动两轮（运动矢量重投影 + 邻域钳制），处理本条时需与那里的结论一并评估，避免混淆归因。

## WG-060：真体积云一层也严重降帧，云形单调

- 现象：用户实测仅开启一层体积云，帧率仍比上一版明显下降，云形也不理想。
- 原因：视线与地表阴影均多次采 3D FBM/Worley，空气及水下散射又重复调用逐点云影；多层体积自遮挡进一步放大像素成本。
- 解决：仅保留两层可选解析平面云，低云/高云各一次求交，短程确定性光照探测按质量档限量；地表云影用同一世界空间覆盖场投影，不含相机位置。移除体积 marching、细胞噪声和空气/水下重复云影采样。启用键改为 `planar-clouds`，默认开启；旧 `volumetric-clouds` 配置留存但忽略。
- 验证：完整构建、Shader 编译及 65 项 Java 测试通过；实际 FPS、云形与地表云影稳定性需实机对照。

## WG-059：云影随玩家移动，远处地表错误地一起变暗或变亮

- 现象：玩家在云下时整片地面受云影，走出云下后仍在云下的地表却受直射日光。
- 原因：之前只从玩家位置计算一次云透射率，写入全局直射光；固定采样高度仅消除了飞越云顶时的亮度翻转，没有形成地表逐地点云影。
- 解决：体积云模式移除 CPU 全局局部云遮挡；地表、粒子、空气/水体散射的直射光由各自世界坐标沿光照方向积分同一云密度场。视线积分仅负责云外观；平面云模式维持原路径。多层风切变和独立采样设置见更新日志。
- 验证：65 项 Java 测试、Shader 编译及完整构建通过；玩家移动时云影位置、雨天亮度与 GPU 帧时待实机验证。

## WG-056：移动时反射与暗处光照收敛缓慢

- 现象：水面倒影、透明物体后的场景和暗处局部光照在移动时发糊或变化，静止片刻后清晰；提高每像素采样数主要增加负载。
- 已确认：当前主视线及其 DLSS 运动 Guide 固定为每像素一次，采样数只重复后续路径；本机配置关闭景深、使用手动曝光，启用 DLSS 光线重建与帧生成。既有玻璃拖影见 WG-006。
- 诊断：视频设置增加光线重建和帧生成开关，供同场景分别排除生成帧与时间重建；修正采样数说明。关闭光线重建时会用原生分辨率显示未降噪的光追画面，不能当作推荐画质设置。
- 用户反馈：关闭光线重建后噪点严重，无法正常游玩；此开关仅保留诊断用途。后续统一排查反射/透射运动 Guide、透明物输入和暗部局部采样，再考虑可调的运动场景画质档。暂不添加无法真正控制 DLSS 历史权重的滑杆。
- 验证：65 项 Java 测试、Shader 编译与 SPIR-V 验证通过，诊断包已部署；水面运动 Guide、折射 Guide 和低照度重建各自的贡献待游戏内对照，尚未声称修复画质。

## WG-058：飞到云层上方后地面日照突然增强

- 现象：地面站立时云遮太阳呈阴天；飞过云顶后，云下地形立即变亮。

- 验证：完整构建和 65 项 Java 测试通过，游戏内天气与高度切换待复测。

## WG-057：体积云分层且俯视地形时漏绘

- 现象：斜视云层呈水平薄片；飞到云层上方看向地形时云消失。
- 原因：初版在固定高度轮廓中只用 8/12/16 个等间距样本；云仅写在 sky-miss 着色器中，地形先命中时不会绘制云。

- 验证：完整构建和 65 项 Java 测试通过，游戏内分层、云顶和帧时待复测。

## WG-055：自动景深被准星前的雨丝瞬间拉焦

- 现象：雨丝经过准星时，景深会突然聚焦到近处；额外的 X 缩放复位键与 C 键的切换行为重复。
- 原因：自动景深只读取准星中心一个深度值，近处雨丝可占据该像素。
- 调整：使用中心及四个对角邻点的深度中值，抑制孤立近处雨丝；雨柱半宽再从 `0.20` 收到 `0.12` 格，移除重复的 X 键绑定。雨丝覆盖整个采样区域时仍可能拉焦。
- 验证：65 项 Java 测试、全 Shader 编译及 SPIR-V 验证通过；雨天跳焦与雨丝外观待游戏内复测。

## WG-054：雨丝近看呈宽而长的矩形条

- 现象：雨点近看像较宽的长方形雨条。
- 原因：每个雨柱由半宽 `0.35` 格的交叉面组成，雨纹理高度坐标每格仅变化 `0.25`，原版雨纹理中的亮纹被放大。
- 调整：只对雨收窄到半宽 `0.20` 格，并将纵向纹理密度提高到 `0.45`；雪的几何与动画保持不变。
- 验证：更新雨雪几何回归断言，65 项 Java 测试、全 Shader 编译及 SPIR-V 验证通过；实机外观待验证。

## WG-053：远景微缩背景过糊、近景轮廓生硬

- 现象：固定焦距不易对准远处目标，整片树林与天空失焦过强；改变原有采样质量，轮廓观感差别仍小。
- 原因：对数距离差持续增大远景模糊半径；单次同深度采样会排除前后景混色，但无法让近处失焦物体的弥散圆覆盖自身轮廓外。
- 调整：用有界逆距离响应控制远景模糊，单独采样更近且失焦的邻近表面，增加可调的前景扩散质量；提供缩放键＋Shift＋滚轮对焦。
- 验证：65 项 Java 测试、Shader 编译与 SPIR-V 验证通过；视觉效果和帧时待实机验证。

## WG-052：景深物体边缘出现闪烁噪点

- 现象：前后景交界的细边和角落出现颗粒，镜头运动时闪烁；远景微缩模式更明显。
- 原因：原模糊盘每像素仅 `8/16/24` 次随机角度采样，且只排除远景样本，允许前景颜色混入失焦背景；显示分辨率颜色与渲染分辨率深度在轮廓处也可能错位。
- 缓解：采样改为固定的成对对称圆盘，双向筛除大深度差样本；提供 `32/48` 次高采样档位。尚不能排除深度分辨率差异造成的全部细边伪影。
- 本轮改动（2026-09-29，由 Reasonix 实施）：按本条目原因重写 `display.comp` 的景深采样与权重——颜色/反向深度改为逐样本双线性、加入亚像素弥散圆下限、模糊半径改由邻域扩散弥散圆驱动、权重改为相对弥散圆的平方双边权重加自采样能量补偿、采样核改为逐像素哈希的黄金角螺旋。对称圆盘与深度差阈值筛选均被替换。因该 pass 在 DLSS-RR 之后没有时间累积，采样核保持时间固定；静止画面应稳定，运动时的残余表现与新引入的过渡区空间颗粒待实机判定。
- 本轮追加（2026-09-29，由 Reasonix 实施）：用户实机反馈"边缘仍闪烁，但过渡好转"。定位到残余闪烁主因是扩散搜索对薄几何的漏检——叶片/草丛只占搜索圆盘面积约 2%，旧的双线性稀疏搜索经常完全采不到它，模糊半径因此在 `0.56 px` 与最大半径之间逐帧跳变（"软化判定"实测无效，因为漏检时样本自身的 CoC 也是背景的小值）。改为最近深度纹素单次读取（`sceneDepthNearest`），同开销下把扩散档位加密到 `16/32/64/96/256/480` 次；合成场景亚像素平移测得极端帧间差 `0.0882→0.0460`、p90 `0.0270→0.0202`。同时修正"远景微缩"的弥散圆上限：原硬编码 `12/24` 像素与显示分辨率无关，换分辨率或窗口尺寸会单纯改变微缩强度，现按显示短边缩放（`12 px @ 1080p`，近处 2 倍）。
- 本轮修复（2026-09-29，由 Reasonix 实施）：用户进一步反馈"大于聚焦距离处调高景深采样可缓解轮廓内噪点、但仍有边缘闪烁；低于聚焦距离处边缘闪烁严重，另有一圈噪点轮廓、轮廓内一层薄膜，以及薄膜与外圈之间的分割线，拉高采样也不能缓解"。定位为深度 guide 的采样方式：DLSS-RR 下 guide 是渲染分辨率，一个纹素覆盖多个显示像素；gather 的中心深度若用最近纹素，近景失焦轮廓内会有连续一段像素继承到背景纹素深度、被判为合焦并返回未模糊的原色，从而形成薄膜与硬分割线，并随镜头逐帧跳变——这与采样数无关，正是"拉高采样无效"的原因。中心深度改用双线性读取；0.5 倍渲染分辨率的合成场景实测帧间差平均 `0.0121→0.0033`、极端 `0.2476→0.0791`。扩散搜索保持单纹素读取：实测其采样方式与密度（单纹素 32 次、双线性 8/16/32 次）对帧间差没有影响，瓶颈在主盘 gather。
- 本轮实现（2026-09-29，由 Reasonix 实施）：用户确认中心深度双线性后"稍微软了点但很微小，边缘还是噪点+闪烁"，要求上时间累积。按本条目早先的判断实施独立历史累积：采样核改为逐帧旋转（黄金比 + R2 低差异序列；固定核会让噪声冻结在画面上，累积将完全无效），与重投影后的上一帧历史按 `0.1` 权重混合。重投影复用世界着色器生成运动矢量的同一构造（上一帧 view-projection × 当前 clip 位置 + 相机位移项），历史只在重投影越界、落到相机之后、或逆距离相对差 `>0.08`（换到别的表面）时丢弃。`RtComposite` 新增两张显示分辨率 `RGBA16F` 乒乓历史图（rgb=颜色，a=解析时用的中心深度），每帧交换并刷新绑定；`RtDisplayPipeline` 的 push constant 由 40 字节扩到 128 字节，描述符由 5 个绑定扩到 7 个。0.5 倍渲染分辨率的合成场景实测帧间差平均 `0.0140→0.0043`，历史接受率 `99.3%`（深度拒绝在轮廓处不过度激进，依赖的正是双线性中心深度）；抖动经核对逐帧去相关。
- 本轮修复（2026-09-29，由 Reasonix 实施）：用户报告"移动时严重拖影、静止转动视角正常"，另有一条规律"越接近聚焦位置边缘闪烁越严重"。按用户要求先做网络调研，TAA 综述指出纯旋转的重投影与深度无关、平移则完全依赖深度/位移，任何误差都会变成错误的历史取样——正好对应"只有平移出问题"。复查代码后确认重投影存在数学错误：反投影结果 `h = inv(curViewProj)·clip` 是齐次点，真实位置为 `h.xyz/h.w`，先前把相机位移加在齐次点上再乘 view-projection，等于把位移项乘了 `1/h.w`（即乘上距离）。解析验证：2 格处历史错位约 `38` 像素、5 格约 `61`、20 格约 `72`、100 格约 `75`，1 格处 `h.w = 1` 恰好抵消、纯旋转位移项为 0——与用户观察完全一致。改为分两步计算（反投影 → 透视除法 → 加位移 → 乘上一帧 view-projection），修正后误差 `0.0000` 像素。"越接近焦平面越闪"另有原因（焦平面附近真实弥散圆仅亚像素，但扩散搜索会把它拉到远处失焦物的半径，盘半径在 0.56 与最大值之间跳变），尚未处理，待修复拖影后重新评估。
- 本轮修复（2026-09-29，由 Reasonix 实施）：用户报告"两种模式拖影都减轻但仍不能正常游玩，夜晚尤其差"，并建议参考 ITRP。核对 ITRP 的架构：它的 DOF 并不自行累积，而是把结果交给下游自研 TAA 统一累积整幅画面，因此天然具备含物体运动的运动矢量、邻域颜色钳制与深度拒绝三样；我们受 NVIDIA 约束把 DOF 放在 DLSS-RR 之后、无法借 RR 的历史，只能做"DOF 专属历史"，此前只用相机运动重投影，完全没有动态物体补偿。本轮补齐两点：(1) 重投影改用 `gMotion`（与 RR 同一张图、含 `gv_motionObjDisp` 物体位移、与 RR 输出天然对齐），push constant 由 192 缩回 56 字节、描述符增至 8 个绑定；(2) 加入 5 点邻域颜色钳制，抑制"每帧固定偏差被累积成条带"。混合权重由 `0.1` 提到 `0.2`（约 5 帧有效窗口）以优先保证移动可用。夜晚更差的原因尚未确证，怀疑与低对比画面下点光源被拉伸更醒目、以及夜间 RR 本身收敛更慢有关，建议实测时用视频设置里的帧生成开关做对照。
- 验证：65 项 Java 测试、全 Shader 编译及 SPIR-V 验证通过；`caustica-0.4.4-dof-motion-temporal-test.jar` 已部署，SHA-256 `2D6E7D258523AF603869387836FECAAA43CBF29323CC398EEEB81BCA4EA493C4`（旧版 `dof-gather`、`dof-spread-fix`、`dof-center-bilinear`、`dof-temporal`、`dof-reproject-fix` 均已禁用）。移动拖影、夜晚表现、远景微缩表现、焦平面附近闪烁与帧时仍待游戏内验证，本条目尚未声称修复。

## WG-051：远处景深几乎看不出失焦

- 现象：准星自动对焦时，远景的景深非常弱，无法形成固定远处焦平面的微缩画面。
- 原因：反向 Z 深度在远处高度压缩，直接比较深度差得到的模糊半径过小。

## WG-035：DLSS/窗口切换后持续低帧，POM 版本基线帧率偏低

## WG-034：视差缝隙侧壁呈薄片堆叠

## WG-033：POM 砖缝闪纹、发白且缺少内部阴影

- 现象：移动时砖边出现细密闪纹；亮处砖缝发白、深度感弱，内部阴影不足。

- 解决：两条路径均先以 `waterHitT × sampledLightDir.y` 恢复垂直水深，再由稳定主光方向重建水面位置。
- 状态：已修复并加入前后表面契约测试。

## WG-010：0.3.3 水下焦散呈现规则网格

- 现象：水底出现容易辨认的均匀周期网格，遮盖自然水波层次。
- 原因：三层 `sin(a)+sin(b)` 亮纹均由规则交叉波组成，再与物理 Jacobian 相乘后周期结构被放大。
- 解决：0.3.4 删除整个人工网格，只保留经过深度过滤、幂曲线柔化和限幅的物理焦散。
- 状态：自动验证通过，等待游戏内确认。

## WG-011：0.3.4 水下焦散呈现平行弯曲亮带

- 现象：俯视水面时，物理焦散形成近似平行的一条条弯曲亮带，规律感明显。
- 原因：四组宏观波方向都集中在主风向附近，Jacobian 聚焦被同向长波褶皱主导。
- 解决：0.3.5 使用两组近风向波和两组交叉涌浪，保持其他水体参数不变。
- 状态：自动验证通过，等待游戏内视觉确认。

## WG-012：0.3.5 水下焦散仍呈现会波动的规则网格

- 现象：交叉涌浪改变了亮纹方向，但大面积水底仍能辨认出整体移动和变形的规则网格，视觉单调。
- 原因：宏观波仍只有四个固定方向，微观波只使用两组交叉方向，所有波长按 `1.5` 等比递减；物理 Jacobian 会放大这些周期交点。
- 解决：0.3.6 以统一的 12 层非谐波频谱替换两个规则方向族，并为每层加入独立二维波峰弯曲及完整解析导数。
- 状态：契约测试和 Shader 编译通过，等待游戏内视觉确认。

## WG-013：短波在长帧间隔下的一阶时间回推失真

- 现象：卡顿后最短波可能跨越数弧度，一阶 Taylor 回推得到错误的上一帧法线，增加运动向量跳变和拖影风险。
- 原因：原逻辑对最长 `0.25` 秒间隔始终使用线性回推，没有考虑短波的高角频率。
- 解决：0.3.6 仅在不超过 `0.05` 秒时使用解析导数回推；更长但有效的间隔精确求值上一帧频谱。
- 状态：契约测试与完整构建通过，等待游戏内卡顿场景验证。

## WG-014：近处浅水缺少水底焦散亮纹

- 现象：中远距离焦散自然且性能可接受，但一至三格浅水的近处沙地几乎没有亮纹。
- 原因：`0.22m` 的浅水有限差分范围会过滤 0.37–0.73m 短波，同时很浅的折射映射接近单位 Jacobian。
- 解决：0.3.7 将近岸采样降至 `0.08m`，并有限增强浅水聚焦相对中性值的偏离。
- 状态：契约测试与完整构建通过，等待游戏内视觉确认。

## WG-015：水体只有单一 Beer 吸收色相

- 现象：浅水近乎完全无色，深度增加后仅向单一颜色衰减，缺少隐约绿色、温暖浅水和蓝青深水的层次。
- 原因：介质只乘 Beer-Lambert 透射，没有水段散射返回；吸收系数也主要由生物群系颜色线性反相得到。
- 解决：0.3.7 使用清水光谱吸收基线和低权重生物群系修正，并从被吸收能量中返回最多 4% 的琥珀至蓝青环境散射。
- 状态：契约测试与完整构建通过，等待游戏内视觉确认。

## WG-016：水体缺少可选距离雾与遮挡光束

- 现象：水体虽然具有深度吸收颜色，但观察水下远处时仍过于通透，且太阳/月亮入水后没有可被建筑截断的可见光束。
- 原因：0.3.7 只有无方向、无遮挡的轻量环境散射，没有视频开关和前向散射相函数。

- 状态：契约测试、Shader 编译与完整构建通过；等待游戏内雾密度、光束边缘和性能验证。
