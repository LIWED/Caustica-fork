# Bug 记录

## WG-031：深水过度透明且缺少独立透明度控制

- 现象：Water Fog Strength 同时改变直达透射与散射雾气，无法独立调节水底能见度；默认深水仍过度透明。
- 原因：`waterEffectiveExtinction()` 将 Water Fog 的散射系数直接加入直达消光，且 `WorldPush.waterTuning.y` 尚未发布独立透明度参数。
- 解决：新增持久化 Water Transparency `0–200%` 滑杆，通过 `waterTuning.y` 发布；水体额外消光按 `0.14 × (1 - clamp(transparency × 0.5, 0, 1))` 计算，Pass A、Pass B 与 Transmission Guide 共用该结果；Water Fog 仅控制翠绿/青蓝散射与丁达尔光束。
- 自动证据：契约先 RED 后 GREEN，锁定配置/UI/双语文本/ABI/三个消费者及 `5m/10m` 数值锚点；聚焦水体 JUnit、两份源码契约和强制真实 Shader 编译通过，ABI 保持 `672` 字节及 `384/388/392/396/400` 偏移。
- 状态：最小修复与自动验证已完成；透明度 × 深度 × 水雾的游戏内画面和 GPU 帧时仍待验证。

## WG-030：Water Fog 强度滑条未参与有效消光

- 现象：Water Fog Strength 滑条已发布，但 `waterEffectiveExtinction()` 忽略其数值，深水水底辐亮度仍占主导。
- 原因：有效消光无条件返回基础吸收，未在水体雾气开启时叠加钳制后的散射消光。
- 解决：仅在 water+fog 启用时，将 `WATER_SCATTERING_COEFFICIENT × clamp(strength, 0..2)` 加入基础吸收。
- 自动证据：波前水体/玻璃契约覆盖 helper 分支、`0..2` 钳制、透射锚点与距离/强度单调性；0.4.4 完整 JUnit `51/0/0/0`、强制 Shader 编译与完整离线构建通过。
- 状态：最小修复已实现；水雾 `0/100/200%`、深水有效透射、水色、生物群系、运动画面和 GPU 帧时仍待游戏内验证。

## WG-029：夜间仍显示水下焦散

- 现象：夜间由月亮作为 active light 时，水下焦散仍然可见。
- 原因：`waterCaustic()` 只依据焦散强度和掠射角计算，没有消费现有的太阳昼夜因子；因此 active moon 仍会驱动焦散乘数。
- 解决：钳制 `worldPush.sunDir.w` 作为太阳焦散权重；夜间权重为零时返回中性 `1.0`，仅以该权重调制最终焦散偏离，不改变月亮辐亮度、可见性或完整 NEE 项。
- 自动证据：波前水体/玻璃契约约束太阳权重、夜间中性返回、最终焦散调制，并禁止将昼夜权重乘入月光辐亮度或可见性；0.4.4 完整 JUnit `51/0/0/0`、强制 Shader 编译与完整离线构建通过。
- 状态：最小修复已实现；昼夜过渡、夜间焦散、月光照明、运动画面和 GPU 帧时仍待游戏内验证。

## WG-027：普通船内部出现紫色矩形

- 现象：普通船和箱船内部出现规则的淡紫色平面；船体其他部分基本正常。
- 原因：Minecraft 额外提交的 `RenderTypes.waterMask()` 仅用于栅格深度/水面遮罩，没有颜色纹理；RT 实体捕获却将其作为普通可见模型处理，无纹理时回退到 slot 0 方块图集并在 closest-hit 中显色。
- 后续：短期从可见 RT 几何中排除 raster-only `waterMask`；若船舱重新出现水面，再增加“自身不可见、仅排除船舱水面”的专用 RT 语义。
- 状态：根因已确认，待修复。

## WG-026：第一人称手臂和手持物品未参与光追

- 现象：手臂与手持方块仍呈现原版栅格效果，整体灰暗，与光追世界的照明、曝光和材质表现不一致。
- 原因：当前 `GameRendererMixin` 明确在世界 RT composite 完成后，将整个 `renderItemInHand` 重定向到 RGBA8 `RtUiOverlay`；该几何不进入 BLAS/TLAS，也不接受路径追踪、RT 阴影或世界曝光。
- 后续：建立独立 RT Viewmodel 层，复用原版同一次手持提交捕获姿态，以 HUD 投影和独立运动信息渲染 HDR 透明结果；RT 失败时保留原版回退。
- 状态：根因与推荐架构已确认，待设计批准和实施。

## WG-025：水面波动、折射扰动与近岸焦散不足

- 现象：非倒影区域几乎看不出水波；水下物体没有明显随水面波动产生的自然折射扭曲；近处水底缺少焦散亮纹。
- 原因：0.4.2 焦散只复用偏长的基础十二层波，缺少能在水底形成细密、交织脊线的独立短波结构；Jacobian 差分尺度又与 LOD footprint 共用，无法分别控制聚焦估计和远距过滤。
- 解决：0.4.3 保留水面十二层波和折射八层波，另加六层仅供焦散使用的短波细节谱与解析二维 warp；基础/细节梯度先合并再统一限幅，并将 Jacobian `0.06` 与 LOD `0.06..0.28` 分离。固定 CPU 镜像回归约束脊线宽度、峰间距、密度、方向、能量、连续性和重基准不变性。
- 0.4.2 实机验收（截图观察）：失败；水底焦散仍由规则、稀疏且近似平行的亮纹/亮带构成，未形成参考图中自然、细密且交织的焦散纹理。截图本身仅证明该可见现象；上述根因由后续源码与数值分析确认。
- 状态：0.4.3 自动契约、数值回归和强制 Shader 编译通过；参考图视觉、运动稳定性和 GPU 帧时待游戏内验证。

## WG-024：水面透射与反射缺少明显深度层次

- 现象：浅水与深水区域的表面透明度接近；深水仍过度显示水底，没有像参考效果那样随光学深度增加而让反射在视觉上占主导。
- 原因：0.4.2 的 `(0.120, 0.095, 0.105)` 对绿/蓝通道吸收过强；Water Fog Strength 还把中性浑浊消光叠加到直接吸收，使水体变暗并削弱翠绿/青蓝层次。
- 解决：0.4.3 将基础吸收校准为 `(0.118, 0.052, 0.058)`；Water Fog Strength 只调节有能量上界的翠绿/青蓝散射，直接吸收保持不变。Pass A、Pass B 与 Transmission Guide 继续共享有效消光。
- 0.4.2 实机验收（截图观察）：失败；水体整体偏黑且失色，缺少参考图的翠绿至青蓝水色层次。截图本身仅证明该可见现象；上述根因由后续源码与数值分析确认。
- 状态：0.4.3 自动透射锚点、源码契约和强制 Shader 编译通过；同机位水色、生物群系与 `0/100/200%` 截图仍待游戏内验证。

## WG-021：空气环境缺少自然高度雾与遮挡体积光

- 现象：陆地空气始终近似完全透明，远景缺少高度和距离层次；建筑遮挡太阳/月亮时也没有连续光柱。

- 状态：契约与 Shader 编译通过；等待游戏内检查雾密度、室内外光柱、运动稳定性和 GPU 帧时。

## WG-020：RT 取消 vanilla world renderer 后雨雪不可见

- 现象：RT 接管世界渲染时，vanilla 天气绘制随 `LevelRenderer.render()` 一起被取消，雨雪完全消失。
- 原因：天气柱只存在于可变 `WeatherRenderState`，既未在取消点复制，也未进入 RT 的 mesh、BLAS 与 TLAS。
- 解决：仅在确认取消前生成不可变快照；每帧转换为重基准交叉 quad，复用粒子上传/BLAS 生命周期，使用独立 rain/snow 纹理、primary-only mask 和 stochastic any-hit alpha。
- 精度修正：逐柱 alpha 镜像 vanilla 的半径平方距离淡出，rain/snow 分别使用 `1.0`/`0.8` kind factor，柱体总宽约一方块。
- 状态：focused JUnit、天气契约、Java 与 Shader 编译通过；游戏内遮挡、视觉密度和性能待验证。

## WG-019：天气参数未改变天空与照明

- 现象：雨、雷和闪电不影响天空、天体、星空或 active sun/moon 直射光，且没有动态云层。
- 原因：`WorldPush.weather` 与 `weatherColor` 已发布，但 miss shader 和 CPU 光源强度尚未消费这些数据。
- 解决：0.4.1 Task 3 增加重基准云高、三 octave 非规则厚云和共享天气透射公式；`weather.z` 来自尊重隐藏闪电选项的真实 flash countdown。独立全值 `cloudAnchor` 保持重基准连续，CPU 镜像局部云透射以统一 NEE 与天体圆盘遮挡，并平滑淡出近水平及超远交点。
- 状态：契约、ABI 生成、Java 主代码和 Shader 编译通过；JUnit 因离线缓存缺失待验证，游戏内视觉确认待执行。

## WG-017：单点水雾遮挡把陆地树木投成水下硬剪影

- 现象：从水下观察时，陆地上的树会以完整、锐利的二维轮廓出现在水雾中，不像连续的阳光遮挡或体积光柱。
- 原因：0.3.8 对整段水体只在中点执行一次二值 `visibility()`，再把该结果乘到整段方向散射；单个遮挡点因此代表了全部水体积分。
- 0.3.9 遗留问题：三点平均仍会把同一遮挡物显示为三个错位轮廓，无法形成沿视线连续延伸的光束。
- 解决：0.4.0 改为 8 层、最大 48 方块的逐段散射积分；每层独立计算可见性和入水光程，并用逐帧分层抖动消除固定阶梯。
- 状态：契约测试、Shader 编译与独立审查修正通过；等待原场景游戏内复测和帧时测量。

## WG-018：水雾强度只增亮散射，水底仍过度可见

- 现象：0.3.9 即使水雾强度设为 `200%`，远处水底仍清晰；深水颜色偏单调蓝色。
- 原因：滑杆只乘散射辐亮度，不参与介质透射；基础吸收的蓝通道又过低。方向散射还只使用主光亮度平方根，丢失实际光色并放大弱月光。
- 解决：0.4.0 让滑杆线性增加近中性浑浊消光，统一用于 Pass A、Pass B、Transmission Guide 和太阳/月亮水下光程；基础吸收改为红最强、蓝略强于绿，散射仅来自浑浊项并保留实际主光 RGB。
- 状态：自动验证通过；等待浅水、深水、正午、月光和 `0/100/200%` 游戏内对比。

## WG-009：焦散前后表面路径使用了不一致的距离语义

- 现象：初版 0.3.3 的背面 SSS 路径会重复推进焦散坐标，主路径也会把抖动射线的斜距直接用于稳定方向。
- 原因：`waterCaustic` 从“水面点＋斜距”改为“接收点＋距离”后，两条调用路径没有同时转换为统一语义。
- 解决：两条路径均先以 `waterHitT × sampledLightDir.y` 恢复垂直水深，再由稳定主光方向重建水面位置。
- 状态：已修复并加入前后表面契约测试。

## WG-010：0.3.3 水下焦散呈现规则网格

- 现象：水底出现容易辨认的均匀周期网格，遮盖自然水波层次。
- 原因：三层 `sin(a)+sin(b)` 亮纹均由规则交叉波组成，再与物理 Jacobian 相乘后周期结构被放大。
- 解决：0.3.4 删除整个人工网格，只保留经过深度过滤、幂曲线柔化和限幅的物理焦散。
- 状态：自动验证通过，等待游戏内确认。

## WG-011：0.3.4 水下焦散呈现平行弯曲亮带

- 现象：俯视水面时，物理焦散形成近似平行的一条条弯曲亮带，规律感明显。
- 原因：四组宏观波方向都集中在主风向附近，Jacobian 聚焦被同向长波褶皱主导。
- 解决：0.3.5 使用两组近风向波和两组交叉涌浪，保持其他水体参数不变。
- 状态：自动验证通过，等待游戏内视觉确认。

## WG-012：0.3.5 水下焦散仍呈现会波动的规则网格

- 现象：交叉涌浪改变了亮纹方向，但大面积水底仍能辨认出整体移动和变形的规则网格，视觉单调。
- 原因：宏观波仍只有四个固定方向，微观波只使用两组交叉方向，所有波长按 `1.5` 等比递减；物理 Jacobian 会放大这些周期交点。
- 解决：0.3.6 以统一的 12 层非谐波频谱替换两个规则方向族，并为每层加入独立二维波峰弯曲及完整解析导数。
- 状态：契约测试和 Shader 编译通过，等待游戏内视觉确认。

## WG-013：短波在长帧间隔下的一阶时间回推失真

- 现象：卡顿后最短波可能跨越数弧度，一阶 Taylor 回推得到错误的上一帧法线，增加运动向量跳变和拖影风险。
- 原因：原逻辑对最长 `0.25` 秒间隔始终使用线性回推，没有考虑短波的高角频率。
- 解决：0.3.6 仅在不超过 `0.05` 秒时使用解析导数回推；更长但有效的间隔精确求值上一帧频谱。
- 状态：契约测试与完整构建通过，等待游戏内卡顿场景验证。

## WG-014：近处浅水缺少水底焦散亮纹

- 现象：中远距离焦散自然且性能可接受，但一至三格浅水的近处沙地几乎没有亮纹。
- 原因：`0.22m` 的浅水有限差分范围会过滤 0.37–0.73m 短波，同时很浅的折射映射接近单位 Jacobian。
- 解决：0.3.7 将近岸采样降至 `0.08m`，并有限增强浅水聚焦相对中性值的偏离。
- 状态：契约测试与完整构建通过，等待游戏内视觉确认。

## WG-015：水体只有单一 Beer 吸收色相

- 现象：浅水近乎完全无色，深度增加后仅向单一颜色衰减，缺少隐约绿色、温暖浅水和蓝青深水的层次。
- 原因：介质只乘 Beer-Lambert 透射，没有水段散射返回；吸收系数也主要由生物群系颜色线性反相得到。
- 解决：0.3.7 使用清水光谱吸收基线和低权重生物群系修正，并从被吸收能量中返回最多 4% 的琥珀至蓝青环境散射。
- 状态：契约测试与完整构建通过，等待游戏内视觉确认。

## WG-016：水体缺少可选距离雾与遮挡光束

- 现象：水体虽然具有深度吸收颜色，但观察水下远处时仍过于通透，且太阳/月亮入水后没有可被建筑截断的可见光束。
- 原因：0.3.7 只有无方向、无遮挡的轻量环境散射，没有视频开关和前向散射相函数。
- 解决：0.3.8 增加默认开启的水体雾气选项；复用水段透射状态，以单次中点可见性查询控制有界前向散射，同时永久保留深水吸收。相机已在水中时，Pass A 消耗的首段散射作为单次像素前缀交给 Pass B，避免朝水面观察时漏算。
- 状态：契约测试、Shader 编译与完整构建通过；等待游戏内雾密度、光束边缘和性能验证。
