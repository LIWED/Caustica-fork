# Bug 记录

## WG-045：雪花向上飘且过白、过实

- 现象：雪花随时间向上移动，尺寸偏大，颜色偏亮且缺少轻透感。
- 原因：雪柱把低处顶点映射到较低 V 值，与原版雪列的顶点到纹理坐标映射相反；原雪宽、亮度和随机可见率偏高。
- 修复：仅对雪反转纵向 UV 并提高 20% 纹理密度，半宽 `0.5→0.4`，近/远可见率 `0.8/0.5→0.62/0.38`，颜色调为中性灰 `(0.43,0.45,0.47)`；雨天不变。
- 验证：61 项 Java 测试、Shader 编译、实际打包 SPIR-V 与测试目录单包校验通过；游戏内观感待复测。

## WG-044：雪花沿固定平面下落且颜色纯白

- 现象：侧看雪花沿两张笔直的交叉平面移动，路径单一，白色雪片与场景光照脱节。
- 原因：每列雪仅有两张全高直立四边形，只有纹理纵向滚动；雪纹理的 RGB 直接用于着色。
- 修复：按高度将雪柱分为最多三段，借鉴 ITRP 的世界位置与时间扰动，使用各列独立相位产生连续的 X/Z 弯曲漂移；上传雪片逐顶点运动向量，保留雨柱和原纹理透明轮廓；雪色改为随光照变化的淡灰蓝。
- 验证：雪柱接缝、重基准、运动与雨柱不变性的聚焦测试，完整 60 项 Java 测试、Shader 编译与打包核对通过；实机雪天画面/帧时待验证。

## WG-043：体积光没有独立的吸收率控制

- 现象：空气及水下光束已有可见效果，但默认对比仍偏弱；现有雾强度和水体透明度滑杆会同时改变非光束画面，无法单独调节光束传播。
- 原因：定向体积散射中的视线与入射光衰减均使用固定系数，没有单独传入可持久化的吸收参数。
- 解决：新增 `0–200%`“体积光吸收率”，默认 `100%` 精确保留上一版；只调节空气/水下定向光束的散射份额与传播衰减，复用 `WorldPush.waterTuning.w`，不改变 ABI 或其他雾与水体透光参数。
- 验证：双语文本解析、58 项 Java 测试、全 Shader 编译、生成 ABI 偏移与打包后的两种介质着色器检查通过；实机画面和帧时待检查。

## WG-042：空气和水下丁达尔光束不明显

- 现象：体积光开启后，树叶/建筑间的空气光束及水下丁达尔效应均难以辨认。
- 原因：空气体积光意外受大气雾开关限制；天空射线的四次遮挡采样平均分散到 512 格，近处遮挡覆盖不足。空气和水下的定向散射系数偏低，受光与阴影区域对比弱。
- 调整：体积光独立于大气雾开关；保持四次空气遮挡采样，但按平方分层覆盖近处 96 格，远处大气雾仍完整解析积分；增强两种介质的定向散射，不提高采样次数。水下仍由水体雾气选项控制。
- 验证：58 项 Java 测试、全 Shader 编译与实际打包 SPIR-V 核对通过；游戏内树叶/窗缝、晴雨和水下光束的画面/帧时待检查。

## WG-041：水花测试包中积水不可见

- 现象：用户报告水花测试包中连先前可见的少量积水都消失；上一版湿地云层测试包曾看到积水。
- 排查：两包的实际积水 SPIR-V 相同，水花改动只在粒子路径；不能仅由包差异确定实机消失的唯一原因。现有积水路径在湿润度为零时完全跳过，低湿润度时阈值也偏高；客户端时间回拨还会清零已积累的湿润度。
- 修复：降雨即恢复原有少量积水斑块，湿润度继续驱动斑块扩展到全覆盖；时间回拨只忽略该次负增量，不清零同一地图的湿润度。保持水花与云层修正。
- 验证：新增时间回拨测试；58 项 Java 测试、全 Shader 编译及实际打包 SPIR-V 核对通过。修复包已部署；游戏内效果尚待复测。

## WG-040：雨水落地水花仍呈不透明蓝色方块

- 现象：雨丝已变灰，但地面偶尔出现明显蓝色像素块，与湿地画面不协调。
- 原因：原版雨天 `WaterDropParticle` 与水花共用 `rain/splash` 蓝色贴图，原粒子使用不透明图层；此前改色仅覆盖天气雨柱，普通粒子仍按贴图 RGB 着色。
- 修复：仅在下雨时标记水滴/水花粒子，保留贴图 Alpha 轮廓，以中性灰着色并通过现有 any-hit 随机透明度降至 30% 可见率；不改雨丝、雪片和其他粒子。
- 验证：57 项 Java 测试、全 Shader 编译及打包校验通过；修复测试包已部署，雨天实机画面和运动稳定性待验证。

## WG-039：阴雨云层无法遮住太阳

- 现象：雨天画面中的太阳圆盘仍呈完整明亮的白色方块，与周围灰云不一致。
- 原因：视线云层虽在最后合成，但太阳圆盘 HDR 亮度很高，仅乘一次云透射率后仍会被显示映射成白色。
- 修复：先单独累积太阳/月亮圆盘辐射，再按同方向云透射率的四次方合成；普通大气和云层本身继续使用原透射率，云隙中的圆盘保持可见。
- 验证：全 Shader 编译与打包检查通过；云层遮挡边缘的实机过渡待验收。

## WG-038：地面积水稀少且像贴图

- 现象：持续下雨后积水仍是少量固定斑块；地面局部只是变暗、降低粗糙度，缺少连续湿膜和明显反射。
- 原因：积水强度直接取当前雨强乘固定阈值噪声，未累计降雨时间；原法线和 `0.065` 粗糙度保留过多干燥材质特征。
- 修复：按游戏 tick 累积地表湿润度，持续大雨约 75 秒全湿、停雨约 120 秒干燥，切换地图重置；先让露天地面整体湿润，再降低积水阈值直至全覆盖。积水层进一步平整法线、降低粗糙度并保留雨时涟漪；复用 `WorldPush.waterTuning.z`，ABI 大小不变。
- 验证：新增持续降雨、停雨、重复帧和切换地图测试；57 项 Java 测试与全 Shader 编译通过。雨开始/全湿/停雨阶段的画面与 GPU 帧时待实机验证。

## WG-037：雨天进入世界后 Vulkan 设备丢失

- 现象：雨天测试包进入已有地图后连续闪退，重新进入仍复现。三份 2026-09-27 崩溃报告中两份为 `VK_ERROR_DEVICE_LOST`，另一份在地形 BLAS compacted-size 查询时收到设备丢失；GPU fault 还报告无效读取。服务端日志显示各维度区块保存完成，未发现存档损坏证据。
- 定位：问题随新增雨天地表路径出现；该路径在 closest-hit 中对积水候选像素发起内联向上光追查询。GPU fault 无法精确归因到单条 Shader 指令，因此将其作为首要嫌疑路径隔离，不能据此断言驱动根因。
- 修复：先停用崩溃包并恢复已知可用的 FPS 测试包；随后移除 closest-hit 内联查询，改由地形构建时 `canSeeSky` 标记雨区露天地面。附近屋顶变动后的下方积水可能要等下方地形重建才更新。
- 验证：修复包通过 55 项 Java 测试、全 Shader 编译与 SPIR-V 验证；打包着色器不含 RayQuery 指令，已进入地图取得雨天画面。该包现已禁用保留；后续稳定性仍需继续观察，存档未修改。

## WG-036：雨点偏蓝且露天地面缺少积水

- 现象：雨柱沿用原版雨纹理 RGB，在光追场景中呈蓝色、过密；降雨只改变天气照明和空气雾，地面仍保持干燥材质。
- 原因：雨片 closest-hit 将 `rain.png` 的颜色直接当作辐射率；实体地形命中没有消费降雨强度或检查头顶遮挡。
- 修复：雨片保留原纹理 Alpha 形状，改用中性灰、较窄交叉片和更低的近远处可见率；降雨生物群系的实体不透明朝上表面，按地形构建时的天空可见性产生世界锚定的积水斑块、反射和细微波纹。雪片、降雪生物群系不变。
- 验证：首版因 WG-037 设备丢失已禁用；后续稳定版雨天画面暴露 WG-038 湿地问题。当前 `caustica-0.4.4-rain-wet-cloud-test.jar` 通过 57 项 Java 测试与全 Shader 编译，雨天户外/屋檐下画面、运动稳定性和帧时待实机检查。

## WG-035：DLSS/窗口切换后持续低帧，POM 版本基线帧率偏低

- 现象：切换 DLSS 或调整窗口后帧率骤降；恢复原设置后仍可持续低于正常值超过 10 秒。用户报告关闭雾气后，同设置较原版约低 20 帧。
- 证据：2026-09-27 历史日志在 2560×1440 切换质量模式后连续约 30 秒为 9–10 实际渲染帧/秒；切回先前模式仍未立即恢复。新 DLSS 特性在该窗口大小仅创建一次，未见逐帧重建循环。
- 已处理：重建时 10 张图像由逐张提交并等待改为一次批量布局初始化，针对切换瞬间停顿；增加 Reflex 和 FG 的分段耗时统计以定位持续低帧。画质不变。
- 已确认的窗口路径缺陷：新交换链可能复用旧句柄，原 Reflex 缓存只按句柄比较，会跳过新对象的睡眠模式设置；现已在成功创建交换链后使缓存失效，修正版已部署，待实机验证。
- 实机复现：2560×1410 DLAA 持续约 3–5 实际帧/秒，GPU 100%、显存 7664/8188 MiB，FG 获取与插帧准备持续耗时均很小；关闭 Reflex 后仍约 90 秒保持 4 帧，排除其为该场景主因。切换前未释放旧 NGX 特性会抬高新图像分配时的峰值显存，已改为待机后先释放旧特性，效果待验证。
- 修正版复现（2560×1440）：首次均衡约 38.7 帧，质量约 14.5 帧，第二次均衡约 34.8 帧；再次进入质量及 DLAA 后，切回质量、均衡、性能分别约 6.7、11.8、16.9 帧。新包仍有高档位后无法恢复的现象，原因未确定；正在采集同一轮显存曲线。此前 7664/8188 MiB 是整机显存读数，不可直接归因于 Caustica。
- 同步采样（Windows 进程专用显存）：DLAA 2560×1410 时游戏约 6380 MiB、实际约 11 帧；20:09:18 切回质量后，前约 10 秒游戏仍约 6460 MiB、实际约 19–21 帧；20:09:30 后显存降至约 5860 MiB，帧率回升至约 25 帧。另一轮 2560×1440 也观察到切回后约 300 MiB 的短暂高位。低帧时 GPU 利用率约 100%、核心频率约 2500 MHz，故不能据此归因 Reflex 等待或明显降频；显存占用与帧率相关，但尚未证明具体驻留方或物理显存耗尽。
- 新增每次输出重建的 VMA 显存快照，分别记录旧 RT/NGX 特性释放后和新 RT 图像分配后；下次复现可与进程专用显存比较，判断是 Caustica 活跃分配还是 NGX/驱动驻留。持续低帧与基线约 20 帧差距的最终根因仍待确认。
- 验证：FPS 显存诊断包已编译并部署，55 项 Java 测试、离线 `assemble` 通过；现已禁用保留，新雨天测试包仍包含该诊断。

## WG-034：视差缝隙侧壁呈薄片堆叠

- 现象：近距离斜视高低起伏材质时，砖缝边缘出现重复台阶；侧壁像平面纹理逐层叠放。
- 原因：固定最多 `32` 步的首交点搜索会跨过高分辨率纹素；交点虽偏移 UV，着色法线仍来自平面法线贴图，未表达高度图的陡壁。
- 修复：根据 UV 射线穿越的高度纹素自适应到最多 `128` 步并增加交点细化；从交点高度梯度和真实 UV 度量计算侧壁法线，陡壁处优先使用它参与光照。
- 验证：生产 Slang `35/35`、全 Shader 编译、材质聚焦 JUnit 和 `assemble` 通过；仍需游戏内动态画面与 GPU 帧时确认。POM 不改变方块几何轮廓。

## WG-033：POM 砖缝闪纹、发白且缺少内部阴影

- 现象：移动时砖边出现细密闪纹；亮处砖缝发白、深度感弱，内部阴影不足。
- 原因：高度通道随材质页使用最近邻采样，造成视差步进的高度跳变；命中点只偏移 UV，没有高度图对主光源的遮挡或微凹陷遮蔽。
- 修复：材质页单独使用线性采样器；在命中点沿当前主光源步进高度图，遮挡值只作用于直射光，并对深缝施加有界遮蔽。颜色图采样、几何和射线拓扑保持不变。
- 证据与状态：生产 Slang 数值检查 `28/28`、全部 Shader 编译、材质聚焦 JUnit 通过；新测试 JAR 已部署，游戏内运动画面、直射光阴影及 GPU 帧时待复测。

## POM-001：资源包高度通道未产生视差

- 现象：带 LabPBR 高度图的砖石等方块只改变法线，倾斜观察仍缺少纹理凹凸深度。
- 原因：CPU 已保留 `_n` Alpha 及其 mip，但命中 Shader 未用高度修正采样坐标。
- 解决：在不透明实体地形的颜色/材质采样前执行有界 POM，按三角形 UV 导数还原视线，采用首个交点细化；共用偏移坐标并对三线性过滤的最高参与 mip 加边界保护。
- 控制：持久化开关及深度滑杆；关闭、零深度、无贴图、远处和掠射角回退；不改变玻璃、水和 cutout 的 alpha/介质交叉。
- 自动验证（2026-09-22）：`23` 项直接 Slang 数值检查覆盖平面、斜坡、首次遮挡、镜像/旋转/缩放 UV、退化几何、深度与图集边界；`29/29` 材质/POM JUnit、Java/全 Shader 编译、独立代码复查通过。全量 Java `75` 项中 `11` 项仍因既有焦散缺失 API/冻结候选失败。
- 状态：2026-09-22 测试 JAR 已部署到 `caustica_test/mods`，旧版已禁用；游戏内轮廓接缝、运动/DLSS 与 GPU 性能待验证。既有 WG-032 的未完成测试不属于此项。

## WG-031：深水过度透明且缺少独立透明度控制

- 现象：Water Fog Strength 同时改变直达透射与散射雾气，无法独立调节水底能见度；默认深水仍过度透明。
- 原因：`waterEffectiveExtinction()` 将 Water Fog 的散射系数直接加入直达消光，且 `WorldPush.waterTuning.y` 尚未发布独立透明度参数。
- 解决：新增持久化 Water Transparency `0–200%` 滑杆，通过 `waterTuning.y` 发布；水体额外消光按 `0.14 × (1 - clamp(transparency × 0.5, 0, 1))` 计算，Pass A、Pass B 与 Transmission Guide 共用该结果；Water Fog 仅控制翠绿/青蓝散射与丁达尔光束。
- 自动证据：契约先 RED 后 GREEN，锁定配置/UI/双语文本/ABI/三个消费者及 `5m/10m` 数值锚点；聚焦水体 JUnit、两份源码契约和强制真实 Shader 编译通过，ABI 保持 `672` 字节及 `384/388/392/396/400` 偏移。
- 状态：最小修复与自动验证已完成；透明度 × 深度 × 水雾的游戏内画面和 GPU 帧时仍待验证。

## WG-030：Water Fog 强度滑条未参与有效消光

- 现象：Water Fog Strength 滑条已发布，但 `waterEffectiveExtinction()` 忽略其数值，深水水底辐亮度仍占主导。
- 原因：有效消光无条件返回基础吸收，未在水体雾气开启时叠加钳制后的散射消光。
- 解决：仅在 water+fog 启用时，将 `WATER_SCATTERING_COEFFICIENT × clamp(strength, 0..2)` 加入基础吸收。
- 自动证据：波前水体/玻璃契约覆盖 helper 分支、`0..2` 钳制、透射锚点与距离/强度单调性；0.4.4 完整 JUnit `51/0/0/0`、强制 Shader 编译与完整离线构建通过。
- 状态：最小修复已实现；水雾 `0/100/200%`、深水有效透射、水色、生物群系、运动画面和 GPU 帧时仍待游戏内验证。

## WG-029：夜间仍显示水下焦散

- 现象：夜间由月亮作为 active light 时，水下焦散仍然可见。
- 原因：`waterCaustic()` 只依据焦散强度和掠射角计算，没有消费现有的太阳昼夜因子；因此 active moon 仍会驱动焦散乘数。
- 解决：钳制 `worldPush.sunDir.w` 作为太阳焦散权重；夜间权重为零时返回中性 `1.0`，仅以该权重调制最终焦散偏离，不改变月亮辐亮度、可见性或完整 NEE 项。
- 自动证据：波前水体/玻璃契约约束太阳权重、夜间中性返回、最终焦散调制，并禁止将昼夜权重乘入月光辐亮度或可见性；0.4.4 完整 JUnit `51/0/0/0`、强制 Shader 编译与完整离线构建通过。
- 状态：最小修复已实现；昼夜过渡、夜间焦散、月光照明、运动画面和 GPU 帧时仍待游戏内验证。

## WG-027：普通船内部出现紫色矩形
